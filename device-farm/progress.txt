## Codebase Patterns
- Use Zustand with persist middleware for state that should survive page reloads
- Backend RBAC permissions are defined as "resource:action" format (e.g., "device:write")
- Frontend permission checks use the same "resource:action" format for consistency
- Login page uses gradient background with card overlay pattern
- Device groups use in-memory storage (dict) - in production, use database
- Group routes follow RESTful pattern: GET /groups, POST /groups, PUT /groups/{id}, DELETE /groups/{id}
- Statistics service uses in-memory lists for session/execution data - production needs database
- TrendChart component supports multiple chart types: line, bar, area, histogram
- Alert service supports Feishu/DingTalk webhook notifications via httpx async client
- Alert rules use cooldown_seconds to prevent notification spam
